# שדות בעמדות — חבילת מסירה

הפרומפט המלא: **`IMPLEMENTATION_PROMPT.md`** — זה הקובץ שמעבירים ל-Claude Code. הוא עומד בפני עצמו: סכימה, JSON, API, צד העובד, צד המנהל, שדה ההערה, שלבים, בדיקות קבלה, QA, החלטות פתוחות ומה לא לעשות.

**בשורה אחת:** לכל מסלול בדיקה (`testing_routes` = סוג פריט + מספר מסלול), המנהל מגדיר לכל עמדה ולכל פריט במארז אילו שדות העובד ממלא. ההגדרה נשמרת כ-JSON לפי **step uid**, עוברת טיוטה → פרסום → גרסאות, וכל פריט מקפיא את הגרסה בקליטה. השדות נכנסים לחלונות **הקיימים** בלי לשנות את המעטפת שלהם. עמדה בלי הגדרה מפורסמת נשארת בדיוק כמו היום.

קוד הבסיס: `amitlin1/testingsite` בקומיט `94c96d8` (= `origin/main` ב-2026-10-13).

## החלטות מוצר פתוחות

חמש החלטות, כל אחת ממומשת בברירת המחדל באופן שאפשר להפוך בשורה אחת (§10 בפרומפט):

1. **לחסום סיום עד שכל שדות החובה והערות החובה מולאו?** ברירת מחדל: **כן** (`GATE_FINISH_ON_REQUIRED`), בלקוח ובשרת. "העבר לחקר" לא נחסם.
2. **עמדות צילום (פירוק/הרכבה): שדות בתוך שלב הצילום, או "שדות בשלב נפרד"?** ברירת מחדל: **בתוך שלב הצילום** (ארטבורד 13). ל"שלב נפרד" אין עיצוב ואין טקסט.
3. **להרחיב את `PopUpTestDialog` מ-sm 600 ל-md 900 כשיש בו שדות?** מומלץ **כן, רק כשיש שדות**.
4. **שדות של עמדה ברמת פריט — משותפים לכל המארזים דרך מסלול הפריט, או override לכל מארז?** ברירת מחדל: **משותף**, עם "צור מסלול נפרד למארז הזה".
5. **באג קיים:** שינוי מזהה של סוג עמדה מעדכן את `testing_routes.test_station_type_id` אבל לא את `route_steps` (`src/app/api/settings/test-stations-type/[id]/route.ts:108-111`). ברירת מחדל: **לתקן בשלב 0**.

שאלות נוספות שעלו (הרשאת פרסום, תוצאה בלי `schema`, עקיפת ההצעה, פרסום של כמה מסלולים יחד, הדוח) — §10.2. סתירות בין ארטבורדים וההכרעה בהן — §10.3. טקסט שחסר בעיצוב — §10.4.

## מה השרת עוד לא מחזיר (וצריך להוסיף)

- **ב-`GET /api/settings/testing-routes`:** `step_uids`, `fields_version`, `draft_rev`, `has_draft` — ושגיאה אמיתית (500) במקום `[]`.
- **הקשר המפה** (`GET /api/settings/testing-routes/fields-context`): מסלול המארז + מסלול כל שורת תכולה, עם טיוטה/פרסום, `shared_with` ושימוש בערכות. היום אין שום endpoint שמחבר מארז למסלולי הפריטים שלו.
- **כיסוי לכל מסלול** לשורת המשנה בבורר "מסלול" ("15/20 תאים מוגדרים") — אין לו endpoint; מקורו ב-spec ולא בארטבורד (לא אומת).
- **הגדרת השדות לשלב הנוכחי של פריט** (`GET /api/testing/station-fields?itemId=`), כולל **`groups` נפרדות לכל פריט במארז** ("לכל פריט" / "שדות {סוג}", ארטבורד 16).
- **כל הכשלים, לא רק הראשון** (`evaluateFields().fails[]`) — כל הארטבורדים מחברים אותם ב-" · " בשורת "מוצע".
- **השפעת פרסום:** פריטים בדרך לכל גרסה, "שטרם הגיעו לעמדה ששונתה · N פריטים", מארזים משותפים, "מולא ב-N בדיקות" לשדה שנמחק.
- **שימוש ברשימות ובערכות:** "בשימוש ב-N תאים", "N תאים משתמשים בגרסה קודמת של הערכה".
- **`/settings/packages?type=`** — מסך המארזים לא קורא query היום (צד לקוח, לא שרת).
