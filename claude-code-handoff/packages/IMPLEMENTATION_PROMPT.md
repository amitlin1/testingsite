# מודל מארזים — פרומפט ביצוע ל-Claude Code

מטרה: להוסיף ל-`amitlin1/testingsite` מודל **מארז** (package) — קופסה שנקלטת מהמשלוח, מכילה כמה פריטים, נפתחת בעמדה אחת ונסגרת בעמדה אחרת. כרגע המערכת מכירה פריטים בלבד.

העיצוב סגור ומאושר. הקבצים הם המקור: כל מסך שמוזכר כאן קיים כארטבורד עובד בפרויקט העיצוב, עם כל הטקסטים בעברית, כל המצבים וכל ערכי העיצוב. **אין להמציא טקסט, צבע או מצב שלא מופיע בארטבורד.**

---

## 0. מילון

| מונח | פירוש | הערה |
|---|---|---|
| **מארז** (package) | קופסה פיזית שנקלטת מהמשלוח | יש לה מזהה, סוג, מסלול, סטטוס — אבל **אין לה מספר סריאלי** |
| **תכולה** | רשימת סוגי הפריטים שסוג מארז מכיל, עם כמות לכל אחד | מוגדרת בהגדרות, נפרשת לשורות בקליטה |
| **פריט** (item) | פריט בודד בתוך מארז | נוצר בקליטה, בעל סריאלי, מתקדם במסלול של **סוג הפריט** שלו |
| **עמדה ברמת מארז** | עמדה שהתור שלה מארזים, לא פריטים | פתיחת מארז, סגירת מארז |
| **עמדה ברמת פריט** | כל שאר העמדות | חשמלית, ויזואלית, מחקר… |

### כלל הזהב של המזהה

מזהה הוא **16 ספרות**: 14 ספרות בסיס משותפות לכל המארז + 2 ספרות סיומת.

```
1005150926000300   ← המארז          (סיומת 00)
1005150926000301   ← פריט ראשון      (סיומת 01)
1005150926000302   ← פריט שני        (סיומת 02)
```

- **סיומת `00` שמורה למארז.** פריטים מקבלים `01` ומעלה.
- המזהה נוצר **בשרת** בשמירה. אין להרכיב אותו בקליינט.
- **תצוגה:** תמיד מקובץ בקבוצות של 4 — `1005 1509 2600 03` — ושתי ספרות הסיומת נפרדות ומודגשות (`font-weight:700`, `#0066cc`). כל מזהה עטוף ב-`direction:ltr; unicode-bidi:isolate` כדי שלא יתהפך ב-RTL.
- בטבלאות דחוסות ובתגים משתמשים בקיצור: `…2600 03`.

## 1. סכימה

```sql
-- סוג מארז + תכולה (הגדרות)
package_types (
  package_type_id    serial primary key,
  name               text not null,
  default_route_no   int  null,          -- ריק ⇒ 1
  created_at         timestamptz default now()
)

package_type_rows (
  row_id             serial primary key,
  package_type_id    int  references package_types on delete cascade,
  item_type_id       int  references item_types,
  quantity           int  not null default 1,
  sku                text null,
  model              text null,
  manufacturer       text null,
  manufacturer_no    text null,
  reference_sku      text null,          -- מק״ט פריט ייחוס לשקילה
  default_route_no   int  null,           -- ריק ⇒ ברירת המחדל של המארז
  sort_order         int  not null
)

-- מארז בפועל
packages (
  package_id         bigserial primary key,
  public_id          char(16) not null unique,   -- 14 בסיס + "00"
  id_base            char(14) not null,
  package_type_id    int  references package_types,
  shipment_id        int  references shipments,
  customer_id        int  references customers,
  route_no           int  not null,
  status             text not null,   -- queue | open | test | wait_items | done
  sku, model, manufacturer           text null,
  opened_at, closed_at               timestamptz null,
  opened_by, closed_by               int null references workers,
  intake_at          timestamptz not null default now(),
  intake_by          int references workers
)

-- קישור פריט⇄מארז: על טבלת items הקיימת
alter table items
  add column package_id       bigint null references packages,
  add column package_suffix   char(2) null,        -- "01".."99"
  add column packed           boolean null,        -- סומן "נארז" בסגירה
  add column pack_decision    text null,           -- packed_anyway | missing
  add column pack_note        text null;

create unique index on items (package_id, package_suffix);

-- עמדות ברמת מארז
alter table station_types add column package_level boolean not null default false;
```

### חוקים שהשרת אוכף

1. **סוג מארז אינו ניתן לשינוי** אחרי הקליטה. עריכה מחזירה `409 PACKAGE_TYPE_IMMUTABLE`.
2. **מארז חייב להכיל פריט אחד לפחות.** הסרת הפריט האחרון מחזירה `409 PACKAGE_LAST_ITEM`.
3. **מחיקת מארז** מוחקת בקסקייד את הפריטים שבו ואת היסטוריית הבדיקות שלהם.
4. **שינוי `item_type_id` של פריט** מאפס את המארז: `packages.status = 'queue'`, `opened_at = null`, כל הפריטים חוזרים לשלב 0, צילומים ומשקלים נמחקים. **היסטוריית הבדיקות נשמרת.** התגובה מחזירה `reset: true` עם מה שאופס.
5. **`status = 'wait_items'`** מחושב, לא נשמר ידנית: המארז סיים פתיחה, אך לא כל פריטיו הגיעו לעמדת הסגירה.
6. **מארז נכנס לתור עמדת הסגירה רק כשכל פריטיו הגיעו אליה.** עד אז הוא לא בתור — אבל חיפוש לפיו מחזיר אותו עם `blocked_by` (רשימת הפריטים החסרים והעמדה שכל אחד נמצא בה).
7. **מסלול תקין למארז** מתחיל בעמדת פתיחת מארז ומסתיים בעמדת סגירת מארז. מסלול שלא — מסומן כאזהרה בהגדרות, ולא חוסם שמירה.

### 3.1 רשימת מארזים — `Packages.dc.html`

**שלד:** טבלה (flex:1) + פאנל צד 340px `position:sticky; top:76px`. לחיצה על שורה בוחרת; הפאנל הוא התכולה.

**חמש עמודות בלבד** (זה מכוון — טבלה בתוך טבלה נדחתה):
1. מזהה המארז + `נקלט {תאריך}` בשורה שנייה
2. סוג מארז + `{לקוח} · {משלוח}` בשורה שנייה
3. פריטים (מספר, ממורכז)
4. סטטוס המארז — גלולה ניטרלית עם נקודה צבועה; אם `wait_items` נוספת מתחתיה שורת ענבר `#a86a1a` עם העמדות של הפריטים שלא הגיעו
5. מצב הפריטים — **שורת מיני-פריטים**: מלבן `20×9px, radius 3px` לכל פריט, צבוע לפי מצבו, עם `title` מלא; מתחתיו `N/M סיימו`

מקרא מעל הטבלה: `טרם נפתח #d4d4dc · ממתין #d97706 · בבדיקה #0066cc · הושלם #1f8a5b · חסר במארז #bf3535`.

עוטפים את הטבלה ב-`overflow-x:auto` עם `min-width:680px`.

**פאנל הצד:** זהות · **מסלול המארז = שני אבני דרך בלבד** (נפתח → נסגר; לא "שלב X מתוך Y") · תכולה (כרטיס לכל פריט עם סיומת, סוג, סריאלי/מק״ט, נקודת מצב) · פעולות: עמוד המארז / מדבקות / עריכה / מחיקה.

**מצב ריק:** `אין מארזים תואמים.` + `שנה את הסינון, או קלוט מארז חדש מהמשלוח.`

### 3.2 עמוד מארז

כותרת זהות → שני אבני דרך + מיני-פריטים → **טבלת פריטים** (מזהה, סוג, סריאלי, מק״ט, סטטוס, התקדמות במסלול עם פס `height:5px`, עמדה נוכחית) → פאנל צד: ציר זמן של **עמדות ברמת מארז בלבד**, וקבצים.

### 3.3 קליטת מארז — דיאלוג 1200px

`height:min(760px,92vh)`, פס צד 288px עם 4 שלבים + כרטיס "המארז שייווצר", תוכן גולל, פוטר קבוע.

1. **משלוח וסוג מארז** — בחירת משלוח, ואז טבלת מה שהוצהר: סוג מארז / הוצהר / נקלט / נותר / בחר. שורה שנותר בה 0 מסומנת "הושלם" ואינה נבחרת.
2. **פרטי המארז** — 6 שדות, 2 בשורה. `סוג מארז` נעול (`background:#f5f5f7`, אייקון מנעול) עם `סוג המארז נקבע בקליטה ואינו ניתן לשינוי אחר כך.`; `מספר סריאלי` נעול עם `אין סריאלי למארז`.
3. **פריטים במארז** — השורות נפרשות מהתכולה. **רק הסריאלי הוא קלט בשורה**; מק״ט/דגם/יצרן/מק״ט יצרן מאחורי קישור "פרטים" שפותח שורת הרחבה עם 4 שדות. Enter בשדה סריאלי מקדם לשורה הבאה (זה בפוטר: `Enter בשדה סריאלי מקדם לשורה הבאה`). תג `מהתבנית` על שורה שנפרשה; `הוסף פריט` בתחתית. אזהרת סטייה מהתבנית כשמספר השורות שונה. שגיאת מסלול לשורה בסגנון אדום עדין (`rgba(191,53,53,0.06)`).
4. **מדבקות** — כרטיס מדבקת קופסה + כרטיס לכל פריט. שלושה כפתורי שמירה: `שמור והוסף מארז נוסף` / `שמור` / `שמור והדפס מדבקות` (כחול).

הכול נשמר בבקשה אחת. המזהים נוצרים בשרת — הפוטר אומר זאת מפורשות.

### 3.4 תורי עמדה ואשפים — `Testing Screen Packages.dc.html`

זה **שינוי במסך הבדיקות הקיים**, לא מסך חדש.

- שני סוגי עמדה חדשים: `פתיחת מארז` (id 5) ו-`סגירת מארז` (id 6), שניהם `package_level = true`, כל אחד עם עמדה אחת.
- כשנבחרת עמדה ברמת מארז — התור מציג **כרטיסי מארז** (grid `minmax(320px,1fr)`): סוג, מזהה, לקוח+משלוח, זמן בתור, קו מפריד, שורת מיני-פריטים + `N פריטים בתכולה` / `N/M הגיעו לסגירה`, קישור `פריטים במארז` שפותח רשימה בתוך הכרטיס, וכפתור `44px` בכחול: `התחל פתיחת מארז` / `התחל סגירת מארז`.
- בעמדת הסגירה, **מעל התור**, באנר ענבר `ממתין לפריטי המארז` עם הפריטים שלא הגיעו והעמדה של כל אחד.
- כשנבחרת עמדה ברמת פריט — הכרטיס הקיים נשמר, ומשתנה בשני מקומות:
  - בראש הכרטיס, במקום `#10421`: המזהה המלא (14 אפורות + 2 סיומת כחולות מודגשות), מתחתיו סוג הפריט, ואז הדגם.
  - מתחת לשדות, **רצועת מארז**: תג `מארז` + מזהה מקוצר + סוג מארז + קישור `פריטים באותו מארז` שפותח את האחים ומסמן את הנוכחי (`הפריט הזה`).
- המונה בפס העליון: `N מארזים` בעמדת מארז, `N פריטים` בעמדה רגילה.

**אשף פתיחת מארז — 6 שלבים.** מחליף את אשף "קליטה וצילום" הישן (8 שלבים), שיימחק.

| # | שלב | תוכן |
|---|---|---|
| 1 | סריקת מק״ט המארז | שדה `52px`, באנר ירוק בזיהוי: `זוהה {סוג} · {N} פריטים · {לקוח}` |
| 2 | צילום הקופסה | 3 אריחי צילום (ייחוס + צילום), ואז `האריזה תקינה?` תקין/לא תקין + הערות |
| 3 | פריטים במארז | כרטיס לכל פריט עם `התחל`; כל פריט עובר תת-זרימה `צילום → שקילה` |
| 4 | ספירה | 3 מונים: נספר בעמדה / נרשם בקליטה / תכולת המארז (תבנית) + אזהרת פער |
| 5 | מדבקות | כרטיסי מדבקה נבחרים |
| 6 | סיום | וי ירוק, `כל פריט ממשיך לעמדה הראשונה במסלול שלו` |

תת-הזרימה לפריט: `צילום` (3 אריחים + תקין/לא) → `שקילה` (משקל ייחוס נעול מול משקל נמדד; חישוב סטייה `±5%` ותוצאה ירוקה/אדומה). **סטפר הפריטים יושב מעל רשימת השלבים בפס הצד** — לא פס התקדמות שני.

מה **ירד** מהאשף הישן, וצריך החלטת מוצר לפני מימוש: בדיקות ה-RU (שלבים 2 ו-6 בישן) — הוצאו כי RU הוא תכונה של סוג פריט ולא של קופסה. שאלת הספירה ("כמה פריטים בקופסה?") וסריקת הנלווים נעלמו כי התכולה ידועה מהקליטה.

**אשף סגירת מארז — 4 שלבים.**

1. סריקת מק״ט המארז
2. **פריטים ואריזה** — שורה לכל פריט. פריט שהגיע: תיבת `נארז`. פריט שלא הגיע: רקע ענבר, `לא הגיע · סיים את המסלול בעמדת X`, וכפתור `נדרשת החלטה` שפותח דיאלוג: `נארז בכל זאת` / `חסר במארז` + **הערה חובה**. הכפתור `המשך` חסום עד שכל פריט סומן או קיבל החלטה (`נדרשת החלטה לכל פריט`).
3. **תקינות האריזה** — 3 אישורים (`52px` כל אחד) + הערות. `סגור מארז` חסום עד שכולם מסומנים.
4. סיום

### 3.5 הגדרות → מארזים — `Package Types Settings.dc.html`

רשימת סוגי מארז (סוגי פריטים בתכולה / סה״כ פריטים / **מסלול ברירת מחדל** / תקינות התכולה) + עורך התכולה לסוג הנבחר.

**חשוב:** המסך **לא יוצר מסלול**. הוא מגדיר **מספר מסלול ברירת מחדל** בלבד — שדה מספרי; ריק פירושו **מסלול 1**. הטקסט בעמוד: `ריק פירושו מסלול 1. המסלול עצמו נקבע במסך מסלולי הבדיקה.` אותו כלל בשורת תכולה: ריק ⇒ `ברירת מחדל 1`.

עורך התכולה: סוג פריט, כמות, דגם, יצרן, מספר יצרן, מק״ט יצרן (אופציונלי), מק״ט פריט ייחוס, מסלול ברירת מחדל, סדר (חצים), מחיקה. שורה שהמסלול שלה לא מתחיל בעמדת פתיחה / לא מסתיים בעמדת סגירה — רקע `#fffdf9` + `המסלול לא עומד בכללי המארז`, ובראש העורך באנר עם קישור `פתח את מסלולי הבדיקה`. **אזהרה, לא חסימה.**

### 3.6 משלוחים — `Shipments Packages.dc.html`

יצירת משלוח לפי **סוג מארז + כמות** (לא פריטים בודדים). עמודות המשלוח: `מארזים שהוצהרו / נקלטו / התחילו / סיימו / נשלחו`. שליחה חוזרת ו-PDF נשמרים כפי שהם.

### 3.7 ארבעה דיאלוגים — `Package Dialogs.dc.html`

1. **הדפסת מדבקות** (880px) — כרטיס מדבקת קופסה + מדבקה לכל פריט, כולם בחירים; presets `הכול / קופסה בלבד / פריטים בלבד`; מדפסת, גודל מדבקה, עותקים (stepper); כפתור `הדפס N מדבקות` שנעשה אפור ולא-לחיץ כשאין בחירה. `.no-print` על כל מה שאינו המדבקה עצמה.
2. **שינוי סוג פריט · איפוס מארז** (560px) — דיאלוג **ניטרלי**; רשימה מפורשת של 4 דברים שיתאפסו; הבטחה ש`היסטוריית הבדיקות נשמרת`; **אדום רק בכפתור** `שנה סוג ואפס את המארז`.
3. **עריכת מארז** (680px) — 6 שדות; `סוג מארז`, `לקוח`, `משלוח` נעולים עם אייקון מנעול; באנר הסבר אפור (לא אזהרה): `סוג המארז אינו ניתן לשינוי`; עורך תכולה; `מחיקת מארז` בשמאל הפוטר.
4. **הסרת הפריט האחרון** (520px) — דחייה מנוסחת, לא שגיאה: `אי אפשר להסיר את הפריט האחרון` + שתי חלופות (`מחק את המארז כולו` / `החלף את הפריט`). כפתורים: `הבנתי` + `מחק את המארז`.

### 3.8 עמוד פריט — `Items.dc.html`

בראש גוף דיאלוג הפריט, **כרטיס "המארז שלי"**: תג `מארז` + מזהה + סוג + סטטוס + קישור `עמוד המארז`; מיני-פריטים + `N/M סיימו`; רשימת האחים כשהנוכחי מסומן `הפריט הזה`. פריט בלי מארז — הכרטיס לא מוצג, והכותרת נשארת `#id`.

### 3.9 תגים בהגדרות — `Settings.dc.html`

- **סוגי פריטים**: סוג שהוא מארז מקבל גלולה `מארז` (`#e6efff` / `#0066cc`) בעמודה נפרדת.
- **מסלולי בדיקה**: שלב שהעמדה שלו `package_level` מקבל גלולה `עמדה ברמת מארז` ליד השם.
- **חיפוש גלובלי** (`TopNav.dc.html`): הטקסט הוא `חיפוש מארז, פריט, משלוח או עמדה`; בתוצאות מארז ופריט נבדלים בתג `מארז` ובסיומת המודגשת.

## 5. סדר עבודה מוצע

1. **סכימה + מיגרציות** + נתוני זרע: 3 סוגי מארז עם תכולה, 5 מארזים במצבים שונים, 2 סוגי עמדה ברמת מארז.
2. **הגדרות → מארזים** — בלי זה אין תכולה, ובלי תכולה אין קליטה.
3. **קליטת מארז** + רשימת מארזים + עמוד מארז.
4. **תורי העמדה** (`package_level` בתגובת התור) ואז **אשף הפתיחה**, ואז **אשף הסגירה**.
5. **משלוחים** לפי סוג מארז + כמות.
6. **מדבקות** והדיאלוגים.
7. **התגים והכרטיסים** במסכים הקיימים (פריט, סוגי פריטים, מסלולים, חיפוש).

## 6. בדיקות קבלה

1. קליטת מארז בעל 3 פריטים יוצרת 4 מזהים: `…00` למארז ו-`…01/02/03` לפריטים, כולם על אותו בסיס 14 ספרות.
2. מארז שלא כל פריטיו הגיעו לעמדת הסגירה **אינו** בתור שלה, אבל חיפוש לפיו מציג את באנר `ממתין לפריטי המארז` עם העמדה של כל פריט חסר.
3. `סגור מארז` חסום עד שכל פריט סומן `נארז` או קיבל החלטה מפורשת עם הערה.
4. שינוי סוג פריט מציג את דיאלוג האיפוס; אישור מחזיר את המארז לעמדת הפתיחה ומשמר את היסטוריית הבדיקות.
5. שמירת סוג מארז בלי מספר מסלול נותנת `route_no = 1`.
6. הסרת הפריט האחרון נדחית עם דיאלוג ההסבר; מחיקת המארז מוצעת כחלופה ועובדת בקסקייד.
7. עריכת מארז לא מאפשרת שינוי סוג — השדה נעול בקליינט ומוחזר `409` בשרת.
8. כל מזהה בכל מסך מוצג מקובץ בקבוצות של 4, עם סיומת מודגשת, ואינו מתהפך ב-RTL.
